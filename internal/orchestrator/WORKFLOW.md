# Workflow integration contract

`NewWorkflow(ctx, store, conn) (*Workflow, error)` migrates workflow tables and starts durable BONNIE v0.20 event/result readers and an outbox dispatcher. Caller owns Store and NATS connection: use the embedded server's trusted in-process connection, not public credentials. Close workflow before closing either dependency. Close cancels and joins its goroutines and does not delete consumers.

Route board mutations through `Workflow.MoveCard(id, status, position)` instead of Store.MoveCard. Todo -> Building atomically snapshots the task, inserts a queued attempt, and reorders lanes in one SQLite write transaction. Reordering Building does not create another attempt. Leaving Building is refused (no cancellation protocol implemented); manual Done is forbidden. Store's legacy API is unchanged and must not be used to bypass these rules.

Tasks use shared `bonnie.tasks`; root provisioning enables targeted subjects for future use. Task UUID is deterministic from card ID and monotonically increasing attempt number. Persisted task payload and identity never change on publish retries. Broker ACK marks publication, not execution. Delivery is at least once, not exactly once outside the broker deduplication window; workers must deduplicate by task identity.

`Attempts() ([]Attempt, error)` lists history; `CardResult(id) (Attempt, error)` returns latest attempt; `Ready(id) (bool, error)` exposes verified readiness. Worker/run/remote-attempt identity is pinned by the first event or result: competing worker executions cannot overwrite it. Events never establish success. Completed results require a plain JSON response `{ "pr_url": "https://..." }`; prose, errors, waiting, and malformed reports remain Building. Result text and full wire JSON are persisted.

`SetVerifier(Verifier)` installs `func(context.Context, Attempt) (bool, error)`. It must independently verify repository/branch, actual PR existence, CI and required reviews; worker claims alone are not evidence. Callback receives immutable task context in TaskJSON plus the reported PR URL. Without a verifier, completed attempts are blocked awaiting verification. Verification is retried periodically, including after restart; false/error keeps Building. Only true from a verifier transactionally sets ready and moves the card to Done, preserving lane ordering. Callbacks must honor context cancellation and be safe to repeat. No provider adapter is supplied here.

`Workers(ctx) ([]presence.Record, error)` discovers live records in `jawa_workers` (30-second TTL, create enabled). Presence is advisory, never a prerequisite for queued shared work. BONNIE's API is Discover, not List. Durable consumers `jawa-workflow-events` and `jawa-workflow-results` are stable; one logical board/database per consumer pair. Unknown tasks are acknowledged; database errors cause redelivery. Poison/invalid protocol messages are retained by BONNIE and retried, not silently discarded.
