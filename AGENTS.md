# AGENTS.md

Jawa is a Go coding agent built on [BONNIE](https://github.com/mark3labs/bonnie)
(`github.com/mark3labs/bonnie`). One binary (`module jawa`, Go 1.27) has two roles:

- **Agent** (`jawa`, `jawa serve`): receives tasks over NATS, edits code, runs
  tests and opens PRs.
- **Orchestrator** (`jawa orchestrator`): a local control plane with SQLite, an
  embedded authenticated NATS JetStream server, and a templ/Datastar web UI
  (Board, Archive, Runs, Agents, Settings).

`README.md` is the user-facing reference. Detailed contracts live next to the
code. Read the relevant one before changing behavior (see [Docs map](#docs-map)).

## Repository layout

| Path | What it is |
| --- | --- |
| `main.go`, `*.go` (root) | Agent entry point, CLI flags, `.env` loading, presence, NATS run API, Go lint diagnostics (`golint.go`). |
| `bonnie_gen.go` | **Generated by BONNIE. Do not edit.** It wires `tools/*`, `instructions.md` and `skills/`. |
| `instructions.md` | The Jawa agent's **runtime system prompt**, embedded in the binary. |
| `skills/` | The Jawa agent's **runtime skills**, embedded via `//go:embed skills`. Each skill is `skills/<name>/SKILL.md`. These are not instructions for you. |
| `tools/<name>/tool.go` | BONNIE tool discovery: the directory name is the tool name, and each exports `Tool()`. Logic lives in `internal/reporttools`. |
| `context/` | The agent's root context files (currently empty). |
| `cmd/submit` | Sample task-submission client (`go run ./cmd/submit`). |
| `cmd/factory-smoke` | Offline browser E2E against the real orchestrator and BONNIE host with a scripted model (`go run ./cmd/factory-smoke`). |
| `internal/orchestrator` | Orchestrator: workflow, store, providers, HTTP server, SSE, templ UI. |
| `internal/orchestrator/db` | Goose migrations, `schema.sql` snapshot, sqlc queries and generated code. |
| `internal/orchestrator/frontend` | Node build and browser-test tooling. It is **not** needed at runtime. |
| `internal/orchestrator/assets` | Built, embedded static assets (`//go:embed assets/*`). |
| `internal/report*`, `internal/runapitoken` | Typed report protocol, bridge, tools and run API tokens. |
| `internal/testmodel` | Fake model for tests. |
| `.bonnie/`, `bin/` | Local journals, workspaces and builds (gitignored). |

## Build, test, lint

Run these from the repository root. CI (`.github/workflows/test.yml`, `sqlc.yml`)
runs the same commands, so run them before declaring work done:

```sh
go build -o ./bin/jawa .
go vet ./...
go test -race ./...
golangci-lint run ./...          # CI pins v2.14.0
```

For a fast loop, scope tests, e.g. `go test ./internal/orchestrator -run TestName -count=1`.
Run the full orchestrator suite before finishing.

### Generated code: it is checked in, so keep it current

CI fails if regenerating produces a diff. Commit the generated output together with its sources.

- **templ:** after editing any `*.templ`, run
  `for f in internal/orchestrator/*.templ; do go run github.com/a-h/templ/cmd/templ@v0.3.1070 generate -f "$f"; done`.
  Use repository-relative `-f` paths so diagnostics match CI. Never hand-edit `*_templ.go`.
- **Frontend assets:** after changing templ classes, `frontend/src/*` or
  Tailwind usage, run `cd internal/orchestrator/frontend && npm ci && npm run build`.
  This rebuilds `assets/app.js`, `assets/style.css`, the service worker and cache version.
  Tailwind only emits classes it finds in `internal/orchestrator/*.templ` and
  the shadcn-templ module sources.
- **sqlc:** after changing `db/queries/*.sql` or `db/schema.sql`, run
  `go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1 generate`. Never hand-edit `db/sqlc/`.
- **BONNIE:** `bonnie_gen.go` is regenerated by `bonnie build` / `bonnie dev`
  when tools change.

### Browser tests

Browser tests live in `internal/orchestrator/frontend` (Playwright). Use them
when changing the UI. See `internal/orchestrator/CONTRACT.md` for the fixture
workflow. Some fixtures are exported by Go tests via `JAWA_*_HTML` and
`JAWA_COMPONENT_FIXTURE` env vars, then checked by `npm run test:*`. Set
`CHROMIUM_PATH` or run `npx playwright install chromium`. For manual checks,
use a disposable server:
`./bin/jawa orchestrator --data-dir /tmp/jawa-test --listen 127.0.0.1:18081 --nats-listen 127.0.0.1:14223`.

## UI components (templ + shadcn-templ)

The web UI (`internal/orchestrator/*.templ`) is built with
[shadcn-templ](https://github.com/axadrn/shadcn-templ)
(`github.com/axadrn/shadcn-templ/v2`, imported directly from the Go module).

- **Before writing or changing UI, read <https://shadcn-templ.com/llms.txt>.**
  It lists every available component and links to its docs, usage and props.
- **Use shadcn-templ components wherever you can instead of writing custom HTML.**
  Check the catalog before hand-writing buttons, inputs, selects, forms/fields,
  cards, badges, alerts, tables, dialogs, menus, tabs, empty states, pagination or similar elements.
  The repo already uses Alert, Avatar, Badge, Breadcrumb, Button, Card, Checkbox,
  Dialog, Empty, Input, Kbd, Label, Select, Separator, Switch, Table and Textarea.
- Only write custom HTML when no component fits, such as page layout wrappers.
  Even then, compose it from existing components where you can.
- When you find a hand-rolled element that a component could replace, prefer
  migrating it to the component.
- **Theme:** style through the existing tokens in `frontend/src/style.css`
  (`--color-primary`, `--color-muted`, etc., mapped to the Jawa robe-brown/sand/amber
  palette). Use Tailwind utilities and component variants. Do not add hard-coded colors or new CSS files.
- **Component JavaScript:** `frontend/runtime.sh` bundles lifecycle, Base UI/Floating UI helpers, Select, Checkbox, Switch, DropdownMenu, Dialog, CopyButton and MessageScroller from the pinned shadcn-templ module. Add any new component runtime to that shared list; no production CDN.
- **Interactivity:** uses Datastar (vendored in `frontend/src/datastar.js`) and shadcn-templ component runtimes; prefer attributes and server-rendered fragments. The only app JS is the Sortable gesture and service-worker registration. Keep stable keyed patch roots intact. See `SSE_UI.md`.
- For new UI or a visual redesign, follow `skills/frontend-design/SKILL.md`.
- Keep the UI responsive (320–1440px), keyboard accessible and touch friendly.
  Update the relevant browser fixture or test when behavior changes.

## Orchestrator rules that are easy to break

- **Workflow, not Store:** route card moves and state changes through `Workflow`
  methods (`MoveCard`, `CancelCard`, `ForceReady`, …), not the legacy `Store`
  mutators. Multi-row changes must share one `Store.writeTx()` transaction. See `WORKFLOW.md`.
- **Typed reports are the only completion evidence.** Never parse natural
  language agent output as a fallback. Done requires independent provider
  verification of the PR, branch, head, CI and reviews (`PROVIDERS.md`).
- **Delivery is at least once.** Handlers must be idempotent and dedupe by task,
  report or interaction identity. Honor context cancellation and use bounded timeouts for provider and NATS I/O.
- **Migrations:** add a new, increasing version under `db/migrations`. Never
  edit an applied migration. Update `db/schema.sql` in the same change and
  regenerate sqlc. Versions 2 and 4 are Go migrations. See `db/README.md`.
- **Secrets:** never log, render or return credentials, tokens, prompts or raw
  provider response bodies. Operational logs carry IDs and states only. Do not
  store auth in browser JS storage.

## Conventions

- Commits and PR titles use Conventional Commits with a scope, e.g.
  `feat(orchestrator): …`, `fix(ui): …`, `refactor(orchestrator): …`, `docs(skills): …`.
- Add a regression test with every bug fix. Tests sit beside the code as `*_test.go`.
- Never commit `.env`, keys or anything in `.bonnie/`. Use `.env.example` for new variables, and document them in `README.md`.
- Pin tool versions (templ, sqlc, golangci-lint, BONNIE) consistently across
  CI, the `Dockerfile` and the docs when you bump them.

Selects are shadcn-templ `Select` via `selectField`, with server-rendered options.
Fragments containing Select/DropdownMenu/Dialog are replace-patched, or option-keyed
inside morph roots. Dialogs are shadcn `Dialog` frames rendered by
`GET /dialogs/{name}`. Never reset forms containing mounted component declarations.
The standalone recovery page still submits an ordinary HTTP POST.
